## How to work
- Editor: open `HollowKin/HollowKin.uproject`. Claude may not have the `unreal-mcp` tools; use `tools/unreal_mcp/*.sh` (HTTP to the editor's MCP server on port 8000). Read its README (gotchas listed there).
- Save in the editor before/after every batch; stop Play-In-Editor before editing assets.
- LFS: `export PATH=/opt/homebrew/bin:$PATH`. `.gitattributes` no longer marks files `lockable` (2026-11-25), so files stay writable. If an old checkout still has read-only files: `chmod -R u+w HollowKin/Content HollowKin/Config`. After every save, grep the editor log for `Cannot remove|Error saving` (save_assets reports `true` even when it failed).
- Commit trailer: `Co-Authored-By: <the model you are> <noreply@anthropic.com>` (last session: Claude Opus 5.5).
- **Game flow:** main menu → NEW ADMISSION → difficulty → **`Maps/City/Lvl_City`** (rainy night street, phone call from Jaz, walk north) → St. Brigid's Clinic door (`BP_LevelDoor`) → **`Maps/Containment/Lvl_ContainmentWing`** (C1–C9, ending → menu). CONTINUE and death-restart open the wing. `Lvl_TestCorridor` is only a sandbox. Scripts that rebuild content: `tools/slice_layout.py`+`build_slice.py` (wing greybox; `--retexture`), `dress_slice.py` (wing props/FX/signs), `place_combat.py` (hazards + elite), `city_night.py` + `build_city.py` (city).
- **Saving the level works:** `AssetTools.save_assets` with an **empty list** (`{"asset_paths":[]}`) writes new and changed level actors (one-file-per-actor). `save_actor` and `save_assets` on the map path do not.
- **Fab:** the editor's `FabToolset` lists your library (`SearchFabMyLibrary`) and installs packs (`InstallFabListing`) straight into the project; sign in once with `FabSignIn`. Downloads run one at a time and are slow. **Loading another level, or a network change (Wi-Fi blip, `Network path changed` in the log), cancels all pending Fab downloads** — don't `load_level` while they run; Play is fine. `tools/unreal_mcp/fabget.sh "<name>" install` searches the library and installs the first match. Downloads stage in `$TMPDIR/FabLibrary/<listingId>` (watch its size for progress).
- Editor preference changed for testing: *Use Less CPU when in Background* is **off** (`EditorPerformanceSettings.bThrottleCPUWhenNotForeground=false`), otherwise Play runs at 3 fps while the editor isn't focused.

## Lessons that cost time (read these)
- **Never name a Blueprint function like a native one** (`Launch` became `ChaosMover|Launch`, `MakeNoise`). Check read-back for odd `Class|...|Name` prefixes.
- **Duplicating a widget keeps calls to the original's functions** (`Class|WBPPauseMenu|DoQuit`); re-create the call nodes (`delete_node` + `create_node CallFunction|X` + `connect_pins` from event output pin 1).
- **Packaged builds:** open levels by full path; list maps in `MapsToCook` (`-allmaps` skipped the corridor); stage ICU data manually; navmesh must be Dynamic (the RecastNavMesh actor is never saved to disk); `ke`/`ExecCmds` cannot trigger widget code reliably.
- Assets already committed are read-only: `git lfs lock <path>` before `save_assets`, else it returns `false`/"Asset does not exist".
- `Widget|SetVisibility` needs literal enum strings (no `select`); casts and `IsValid` end the flow, nest the rest inside `(:then ...)`.
- **Blueprints with a same-named function get cross-wired.** `BP_BreakerPanel`, `BP_SaveTerminal` and `BP_EndingTrigger` all had `OnTouched`; the first two were calling `BP_EndingTrigger`'s, so they did nothing. `CallFunction|<Name>` in the DSL also resolves to the wrong class. Give every Blueprint function a unique name (`BreakerTouched`, `TerminalTouched`, `EndingTouched`) and compile before wiring calls to a new function (use `:Param` keyword args).
- DSL read-back is lossy: it prints other objects' variables with a wrong class (`Class|BPHollowSave|GetFuses` on BP_Max) and bools as `|GetbX`. When writing: bool getters drop the `b` (`Variables|Default|GetDead`, `SetPowerOn`); another object's vars are `Class|BPMax|GetFuses obj`. To change one value, prefer `find_nodes` + `set_pin_value` over rewriting a graph.
- `set_properties` colours take 0–1 floats as a JSON object (`{"r":1,"g":0.5,"b":0.2,"a":1}`); the `(R=..)` string silently becomes black.
- The level uses **manual exposure** tuned for the flashlight: point lights need ~30–200 cd to read.
- Testing in Play without hands: `set_actor_transform` on `UEDPIE_0_...BP_Max_C_0` teleports Max, and overlaps fire on teleport (that is how the fuse→breaker→door→ending chain was verified). `time.sleep` inside `execute_tool_script` blocks the game thread. Long scripts can exceed the old 120 s `ct.sh` timeout (now 600 s). Drones near the teleport target will kill Max in seconds; C5 has two, C7 has the guard.
- The over-the-shoulder camera sits 40 cm right of Max, so a zero-width camera trace grazes past targets that look centred; `FirePistol` now uses a 12 cm sphere sweep.
- **`write_graph_dsl` leaves the old nodes behind** (dead, unconnected to the exec flow). Run `tools/unreal_mcp/prune.sh <graph>` after a rewrite; `nodeinfo.sh <graph> [type]` lists nodes with their pin values (read-back hides values such as component tags).
- Write tag lookups exactly like `gen.py`'s `T()` helper: `(Utilities|Array|Get(acopy) (Actor|GetComponentsbyTag :ComponentClass "..." :Tag "Pistol") 0)`. Positional args dropped the tag (became `None`).
- Attaching with `SnapToTarget` resets a component's relative rotation, so a rotation set in the Blueprint defaults is lost. The pistol is now pointed along the aim direction every frame in `AimFlashlight` (M1911 barrel is the mesh's −X axis).
- `CaptureViewport` renders the editor world, not Play; setting `bAiming` by property does not play the aim pose. Gun look needs a human check.
- **Committed level-actor files are read-only (Git LFS lockable), and `save_assets` returns `true` even when it could not write them.** The retexture of all 94 blocks and the removal of replaced props silently failed this way (log: `Cannot remove ...`; validator: `soft references a missing package`). Old prop files left on disk would have loaded as duplicates. Fix used: `chmod -R u+w HollowKin/Content/__ExternalActors__/HollowKin/Maps/Containment/Lvl_ContainmentWing` (+ the `.umap`) before saving (solo project, so no per-file locks), then `git rm` the stale files. After any save, grep the editor log for `Cannot remove|Error saving`.
- `set_pin_value` does not mark the asset dirty; `save_assets` then silently skips it (WBP_Difficulty lost its edit). Make any other edit (e.g. `set_node_position`) or check `AssetTools.is_dirty` before saving.
- Auto-import: copying files into `Content/` imports them (bAutoCreateAssets is on); **deleting those source files afterwards opens a modal "Delete Assets" dialog that freezes the editor** until the developer clicks Cancel. Keep sources outside Content (`HollowKin/Fonts_src/`).
- zsh: `"$M:ApplyX"` is parsed as the `:A` modifier — always write `"${M}:ApplyX"`.
- A Blueprint function named `Notify` was invisible to other Blueprints (name clash); use distinctive names (`ShowNote`).
- Screen recordings from the developer land on the Desktop; the filename has a narrow no-break space before `PM`, so use a glob. Frames can be extracted with a small AVFoundation Swift script (see session notes) because ffmpeg is not installed.
